# LPDDR6 JEDEC 正文差异分析方案

本目录回答三个问题：怎样区分正文改写与规范变更、怎样按章节展现差异、怎样评测结果。适用前提是已有两版解析结果，包含章节树、段落和原文定位信息。

**推荐路线：全文覆盖的结构对齐 → 要求级比较 → 上下文与引用检查 → 分层证据报告。** 语义相似度用于寻找对应段落，不能单独判定规范是否改变。

这是设计交付，不是已经完成真实 LPDDR6 验证的产品。尚未接收你的两个解析文件；本目录中的参数、章节号、命令及句子全部是人工虚构示例，不代表 LPDDR6 的真实要求。这里没有上传 JEDEC 原文或公司数据。

## 为什么不能直接逐段做 diff

段落位置变化不等于删除再新增；段落拆成两段不等于新增要求；句子改写不等于行为改变；句子完全没变，也可能因上级条件或引用目标变化而改变适用含义。因此，需要同时记录结构变化和语义变化。

已有 [harness_v2](../harness_v2/README.md) 可以承担工具执行、文件输出和内部模型接入。本方案是它的业务层扩展设计，当前 V2 的稳定键比较尚未实现这里的跨版本语义对齐。公司模型协议可复用，但不要把原有 exact-key diff 宣称为语义 diff。

## 优先落地顺序

1. 接入实际解析 JSON；保留原文和坐标，建立全部段落的覆盖账本。
2. 做章节映射、段落候选、拆分合并与移动识别；保留不确定匹配。
3. 上线数值、单位、否定、条件、规范强度的确定性检查，再接内部模型做要求抽取和解释。
4. 输出章节树与带证据的差异卡片；建立 200–300 个双人标注单元的试验集。
5. 扩充到冻结的独立测试集，验证关键变更召回与审阅工作量后，再决定自动化程度。

以上数量是试验规模建议，不是性能承诺；具体投入取决于真实文件结构、内部模型能力和专家可用时间。
