# V2 验证记录

日期：2026-11-01；Windows / Python 3.12.14。

## 独立性

- 新子项目 `harness_v2`，不导入上一级 `kg_harness`。
- 创建独立虚拟环境时使用 `venv --without-pip`，没有安装第三方包。
- 验证使用 `python -S` 禁用 site-packages 加载。
- AST 导入检查确认运行代码仅导入 Python 标准库及本项目模块。
- 模型地址无默认值；CLI 的 agent 命令必须显式提供配置。
- 没有调用外部模型服务，也没有读取当前聊天或其他产品的模型凭据。
- 源码压缩包已解压到独立目录，以 `python -S` 执行离线 demo 成功：工具错误 0，生成三个真实输出文件；包内没有虚拟环境、公司私有配置或运行日志。

## 自动化测试

36 项测试：35 通过、1 跳过，0 失败。本次耗时 4.065 秒。

覆盖文件读写/修改、哈希冲突、只读输入与越界访问、命令执行/超时/输出限制、KG 版本隔离、差异计算、导入回滚、任务状态与循环限制、模型目标允许列表、认证配置、协议解析及错误修正。

流式解析测试覆盖单字符缓冲、中文和转义、整数/指数边界、元数据位于 sections 后、重复根键、非法 JSON、单值大小限制及逐章节产出。

跳过项：符号链接越界测试；当前 Windows 不允许创建无特权符号链接。

HTTP 集成测试启动进程内 127.0.0.1 临时服务，以脚本化响应分别验证 chat_tools 和 json_actions 的完整链路：真实 HTTP 请求 → 工具调用 → 磁盘文件 → 工具结果回传 → 最终响应。还验证了 302 重定向拒绝及环境代理不被继承。测试服务不是真实 LLM，不能据此声称模型推理质量已验证。

当前执行沙箱允许监听但限制连接回环端口，第一次受限运行因此有三项 HTTP 测试失败；在允许回环连接的测试权限下复跑后全部通过。没有使用外部网络服务替代测试。

## CLI 与产物

- `demo`：8 步，工具错误 0；真实写入、读取、修改及差异导出。
- `--executor trusted-local demo`：11 步，工具错误 0；额外生成并运行 Python 脚本，读取产物确认执行成功。
- `compare --old A --new B`：两项修改、一项删除、一项新增，完整输出 JSON/Markdown。
- `ask --version A --question PARAM_X`：按 A 版返回关键词证据及源 JSON Pointer。
- `doctor`：本地校验配置；不发送模型请求。

## 大文件导入

`python -S scripts/benchmark_import.py --mb 200`：

- 合成 JSON 210,845,309 字节，约 211 MB / 201 MiB。
- 13,107 个章节/记录。
- 导入 4.443 秒，包括两遍解析、文件哈希、SQLite 与 FTS5 索引写入，不包括数据生成。
- 导入后查询成功，返回 8 条受限命中结果。
- 运行原始指标见 `benchmark-result.json`。

这是许多小章节、重复文本的合成输入，不代表真实 JEDEC 的图结构、表格或单章巨大文件；没有测峰值内存，不作真实业务性能保证。

## 未验证与限制

- 公司真实模型的服务协议、认证、TLS 与任务质量尚未验证，需在公司环境配置后接入。
- Docker 后端未实测；当前环境无 Docker。trusted-local 不提供系统隔离。
- 没有真实 JEDEC 样本，格式、稳定 ID 和源文档证据需进一步适配。
- 没有多租户并发、原子跨进程权限保证、崩溃自动续跑和 exactly-once 保障。
