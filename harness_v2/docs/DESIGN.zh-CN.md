# V2 设计：不依赖厂商 SDK 的 Agent Harness

## 目的

公司环境不能使用 Claude Code / Codex SDK 及其模型服务，因此本版本不嵌入这些组件，也不默认连接任何外部模型地址。使用公司批准的 Python、模型服务与执行环境，独立实现所需能力。

本版本复用我们在 V1 中写的文件/KG/执行工具，重写模型接入并去掉第三方解析依赖。它是机制级独立实现，不是“原版 Codex/Claude Code harness 已被移植”的宣称。

## Harness 包含什么

文件读写只是工具层。完整的最小链路是：

```text
用户任务
  → 模型适配器（内部服务）
  → 结构化调用
  → 工具注册表、参数与权限检查
  → 文件 / 执行 / KG 工具
  → 执行结果或错误
  → 模型继续决定下一步
  → 文件产出与任务状态
```

RAG 是获取证据的技术，仍可作为工具之一。是否能写文件，由程序实现与系统权限决定，与模型品牌和是否使用 RAG 没有必然关系。

## 模型与执行环境解耦

Agent 只依赖 `model.complete(messages, tools)`。模型适配器负责把内部消息转换成企业接口格式，返回统一的 assistant 消息/工具请求。工具函数不需要知道模型来自哪里。

两种内置协议共用 HTTP transport：原生工具调用；以及纯文本模型输出 JSON 动作。后者通过严格解析和工具注册表执行请求，不对任意输出使用 eval/exec。内部接口若不同，只改适配器。

请求目的地由操作员配置，模型和 KG 内容都不能设置 endpoint、凭据或执行模式。客户端要求允许列表、拒绝重定向、校验 TLS、不继承环境代理。令牌只读取明确指定的变量，不保存到运行状态。

这些是应用边界，不是网络隔离产品。允许列表可以被操作员配置为任意域名，程序不自动判定其公司归属；DNS 与出站访问应由部署环境控制。可信本机执行的脚本仍能访问系统资源，必须与模型客户端的限制区分。

## 数据层

源 JSON 保留章节嵌套，通过适配器转换为按版本隔离的章节、实体和关系记录。SQLite FTS5 提供关键词检索；证据包括版本、记录 key 和源 JSON Pointer。

标准库流式解析避免一次加载整个文件；每个顶层章节仍整体解析。两遍读取支持任意根字段顺序。对单个值设置上限，防止把单章极大文件误称为低内存可处理。

差异比较依赖稳定 key。它能处理条款编号变化，但不能自行证明身份对齐正确；也不将算法产生的关系解释成原文事实。真实来源、解析器/图算法版本和业务验收标准还需接入。

## 执行和权限

默认工具可读工作区、仅写 work/outputs，原始 inputs 与内部 .state 不可被文件工具修改。覆盖基于当前哈希，编辑要求唯一匹配。命令执行必须由操作员启用。

trusted-local 只用于可信开发任务，不是隔离边界。Docker 模式给出最小挂载、无网络和资源限制配置，但需要实际部署验证；可以替换成公司的容器/作业平台。文件工具策略不能代替 OS 沙箱。

运行日志记录工具调用前后的事件，便于排错；当前不自动重放崩溃前的写操作，也不承诺自动续跑。completed 表示模型停止调用，不等于业务验证通过。

## 当前交付边界

已交付文件操作、程序执行接口、独立循环、两种模型协议、上下文上限与大结果落盘、运行记录、KG 检索和差异导出。

尚未交付：对商业 harness 的源码移植、生产级上下文压缩与恢复、多租户并发、安全审计、真实模型质量评估、语义条款对齐及 JEDEC 专家验证。现阶段不需要多 agent 即可验证任务闭环。
